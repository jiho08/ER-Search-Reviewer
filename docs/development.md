## 2026-09-14 · 시즌별 전체 전적 조회

실제 API에서 응답 `next`와 `?next=`로 다음 경기 묶음을 조회하는 동작을 확인했다. 시즌 선택 시 해당 시즌의 제공 가능한 기록을 끝까지 수집하고 100경기 표시 제한을 제거했다. 진행 상황, 일시 중지·재개, 오류 후 기존 기록 유지, 중복 제거, 다른 시즌 제외를 처리했다. 그래프 기본 기간은 시즌 전체이며 과거 시즌은 종료일까지 표시한다.

공식 누적 시즌 경기 수와 확보한 상세 기록 수를 구분해 보여준다. 최근 90일·닉네임 변경 전 기록 제한은 남아 있어 조회 완료를 시즌 전체 보장으로 표시하지 않는다. 리뷰는 화면이 수신한 페이지 범위를 서버에서 재구성하고 그중 최근 최대 100경기를 분석한다. 일시 중지한 요청이 서버에서 뒤늦게 완료돼도 분석 표본이 늘어나지 않도록 보완했다.

물방개 시즌 12를 실제로 33페이지 조회해 랭크 170경기를 확보했으며 공식 누적 170경기와 일치했다. 기록은 한국 시간 8월 13일부터 9월 13일까지였다. 34개 자동 테스트, 타입 검사, lint, 빌드, 로컬 HTTP 스모크 검사를 통과했다. 실제 Codex 모델 호출과 외부 배포는 하지 않았다.

## 2026-09-14 · 날짜별 RP와 경기 결과 표시 수정

RP 그래프를 한국 시간의 경기 시작일 기준으로 묶고 최근 7일·30일·90일을 선택하도록 변경했다. 일별 RP는 그날 마지막 경기의 종료 점수, 일별 증감은 제공된 증감의 합계다. 조회되지 않은 날과 누락 점수는 빈 값으로 유지하며, 기간 선택은 이미 조회된 경기 범위에 적용된다.

1등의 기존 색상을 유지하고 2~3등은 파랑, 탈출 성공은 초록, 탈출 실패는 빨강으로 표시한다. 1등 외에는 공식 탈출 결과가 순위 색상보다 우선한다. 순위 흐름을 제거하고 실험체별 표를 승률·RP 증감·경기 수·평균 TK/K·평균 딜량·평균 시야 점수·평균 동물 딜량으로 구성했다.

29개 자동 테스트, 타입 검사, lint, 빌드, 로컬 HTTP 스모크 검사를 통과했다. 실제 물방개 전적 10경기에서도 동물 피해량과 탈출 상태를 확인했고, 날짜별 집계는 9월 12일 3경기·+73 RP, 9월 13일 7경기·+205 RP로 검증했다. 이번 변경에서는 실제 Codex 모델을 추가 호출하지 않았다.

## 2026-09-14 · 정상 닉네임 검색 실패 수정

실제 닉네임 조회는 HTTP 200으로 성공했지만 응답 식별자 이름이 `user.userId`여서 문서 예시의 `user.uid`만 확인하던 코드가 잘못된 404를 반환했다. 실제 응답 형태로 동일 오류를 재현하는 테스트를 먼저 추가한 뒤 두 이름을 호환 처리했다. 식별자 형식 오류는 닉네임이 없다는 안내와 구분해 502로 처리한다.

수정된 사이트의 공식 API 연동으로 `물방개` 실제 전적 10개, 시즌 12의 7,030 RP와 시즌 성적 조회 성공을 확인했다. 이제 이 키의 인증과 기본 전적 조회는 동작한다. 이전 403은 당시 관측 기록이며 현재 상태를 뜻하지 않는다. 응답 진단에서는 키나 식별자 값을 출력하지 않았고 `.env`를 변경하지 않았다.

## 2026-09-14 · 이미지·티어·상세 전적 확장

사용자가 지정한 DAK.GG 물방개 전적 화면의 정보 구성을 참고했다. 라임·흑연색 팔레트를 유지하고 현재 시즌 티어·RP·순위, RP 추이와 경기별 증감 그래프, 12개 지표, 실험체별 성적 표, 캐릭터·장비·특성·전술 스킬 이미지를 추가했다. 이미지는 공개 카탈로그의 검증된 URL을 사용하며 21개 예시 이미지의 HTTP 응답과 이미지 형식을 확인했다.

현재 시즌 랭크는 공식 시즌·랭킹·누적 성적 API를 조인한다. 시즌 정보가 없으면 현재 시즌을 추측하지 않고, 순위 요청이 실패해도 최근 경기를 표시한다. 점수 그래프는 같은 시즌의 실제 제공값만 연결하며 절대 RP가 없으면 증감 그래프를 사용한다. 메테오라이트 이하의 단계는 공식 기준으로 계산하고, 추가 승급 조건을 확인할 수 없는 고 RP 구간은 미스릴 이상으로 표시한다.

25개 자동 테스트, 타입 검사, lint, 사이트 빌드, 로컬 HTTP 스모크 검사를 통과했다. 0/미제공 구분, 시즌 분리, RP 누락과 티어 경계값, 시즌 API 일부 실패 복구, 기존 Codex 연결 계약 유지를 검증했다. 이번 확장에서는 ER 개인키 확인과 실제 Codex 모델 호출을 반복하지 않았다. 실제 플레이어 신규 항목 검증은 ER 키 활성화 이후 남아 있다. [조사 근거와 제약](research/player-dashboard.md)에 데이터 범위·출처·이미지 갱신 방법을 정리했다.

## 2026-09-14 · Codex 계정 리뷰 연결

사용자의 선택에 따라 별도 OpenAI API 키 대신 현재 PC의 Codex ChatGPT 로그인을 사용하는 로컬 연결을 추가했다. Node.js 브리지가 표준 입출력으로 Codex App Server와 통신하며 기존 분석 도구를 재사용한다. 사이트 서버에서 전적을 다시 확보하고 브리지는 고정된 전적 스키마만 받는다.

실제 계정의 예시 3경기 분석과 사이트 HTTP API를 통한 `engine=codex` 응답을 확인했다. 전적 조회·생존 분석 도구 호출, 표본 한계와 가상 데이터 표시를 확인했다. 18개 자동 테스트와 타입 검사·lint·사이트 빌드가 통과했다. Codex 로그인 정보는 읽거나 복사하지 않았으며 별도 브리지 인증 토큰만 Git에서 제외된 `.env`에 생성했다.

연결 과정에서 Worker의 `redirect:error` 미지원과 Codex 실행 환경 전체 비활성화 시 분석 도구도 막히는 문제를 확인했다. 리다이렉트를 자동으로 따르지 않는 `manual` 검사로 변경하고, Codex의 명령·파일 편집·외부 기능을 개별 비활성화했다. 실제 사용 한도 오류의 문자열 형태와 필수 분석 도구 누락, 초기화를 포함한 전체 제한 시간도 검증에 반영했다.

`npm start`가 빌드 디렉터리 대신 루트 `.env`를 읽도록 절대 경로를 전달하게 변경했다. 빌드된 Worker에서도 예시 20경기의 종합 리뷰와 네 분석 도구 실행을 실제 검증했다. ER 개인키의 초당 1회 제한에 맞춰 요청 간격도 1.1초로 보완했다. 입력된 ER 키로 `/v2/data/Character`를 요청했으나 `403 ForbiddenException`을 받아 본인 전적 검증은 남아 있다. 공개 배포는 하지 않았다. 실행과 제한은 [Codex 연결 안내](codex-setup.md)에 정리했다.

## 2026-09-14 · 첫 로컬 구현

### 목표와 범위

과제 문서의 자유 주제로 이터널 리턴 전적 검색·개인 리뷰를 선택했다. 첫 범위는 닉네임 조회, 최근 경기 표시, 필터·지표, 리뷰 생성까지 이어지는 한 흐름이다. 참고 서비스 이름은 아디나의 분석실이며 디자인이나 기능 전체를 복제하지 않았다.

### 공식 API 조사에서 반영한 변경

최신 문서의 UID 기반 경로를 사용했다. 이전 사용자 번호를 사용하지 않는다. 경기의 `characterNum`, `playerAssistant`, `playTime` 필드를 정확히 연결했고, RP 누락을 0으로 대체하지 않는다. 시간대가 없는 시각은 추측하지 않는다. 자세한 출처와 미확인 사항은 [API 조사](research/eternal-return-api.md)에 기록했다.

### 구현 결정

- 브라우저에는 정규화된 최소 전적만 전달하고 API 키는 서버 환경 변수에 둔다.
- 규칙 분석도 등록된 도구를 주제에 따라 선택·실행하도록 만든다.
- 실제 AI에서는 모델의 함수 호출을 실행하고 도구 출력과 call_id를 연결해 다음 요청에 전달한다.
- AI 오류가 발생하면 기본 분석으로 대체하되 화면에 대체 사실을 명시한다.
- 통계와 리뷰는 같은 모드·실험체 범위를 사용한다. 오래된 비동기 결과가 새 플레이어·필터의 리뷰를 덮어쓰지 않게 요청 번호를 확인한다.
- 예시 모드는 가상 기록으로 명시하며 유료 모델을 호출하지 않는다.

### 발견한 문제와 해결

1. **Windows 폴더 이름의 `&` 문자 때문에 npm postinstall 실패**: cmd.exe의 패키지 실행 shim에서 경로가 분리됐다. Windows의 설치 자식 프로세스만 PowerShell을 사용하도록 변경해 설치를 완료했다.
2. **새로고침이 캐시를 그대로 사용**: 화면의 새로고침 버튼이 `refresh=1`을 보내도록 연결했다. 일반 검색에는 60초 캐시를 유지한다.
3. **정렬 전 100개 제한으로 최신 기록 누락 가능**: 응답 전체 정규화·중복 제거·정렬 후 제한하도록 수정했다. 오래된 순서로 101개를 받은 테스트로 검증했다.
4. **순위 미제공 값이 있는 비교 구간**: 구간 길이 대신 유효 순위가 각각 최소 3개인지 확인해 잘못된 개선 수치를 막았다.
5. **브라우저 API 입력 조작**: 리뷰 요청 스키마에 전적 수치 필드를 허용하지 않고, 서버가 전적을 다시 가져오게 했다.

### 검증 범위

13개 단위 테스트, TypeScript 검사, 작성 코드 lint, 클라이언트·서버 프로덕션 빌드를 실행했다. 자동 테스트는 공식 API·OpenAI 모의 응답을 사용한다. 브라우저에서 예시 전적, 모드 필터, 경기 상세, 리뷰 생성, 실행 도구 표시를 확인했다. 1440px·390px·320px 화면에서 가로 넘침이 없는지 확인했고, WebMCP 검색의 정상 입력·빈 입력 거부를 확인했다. 개발 서버와 빌드된 Worker 서버 양쪽에서 HTTP 검증 스크립트가 통과했다. 실제 계정 키를 이용한 전적·AI 응답 검증과 외부 배포는 아직 남아 있다.
